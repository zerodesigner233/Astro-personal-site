Smooth animations make web interfaces feel alive. But poorly implemented animations can tank your frame rate and frustrate users.

## The 60fps Target

Each frame has about 16.67ms to render. Exceed that budget, and the browser drops frames.

## GPU-Accelerated Properties

Only two CSS properties trigger GPU acceleration without side effects:

- `transform`
- `opacity`

Everything else (width, height, top, left, margin) causes layout recalculation.

```css
/* Bad — triggers layout */
.element { top: 100px; }

/* Good — GPU accelerated */
.element { transform: translateY(100px); }
```

## will-change

Tell the browser to optimize a property ahead of time:

```css
.animated { will-change: transform, opacity; }
```

Don't overuse it — each `will-change` creates a new compositor layer.

## requestAnimationFrame

Always animate with `requestAnimationFrame`, not `setTimeout` or `setInterval`:

```js
function animate(timestamp) {
  element.style.transform = `translateX(${Math.sin(timestamp / 1000) * 50}px)`;
  requestAnimationFrame(animate);
}
requestAnimationFrame(animate);
```

## Reducing Paint

Use `transform: scale()` instead of `width/height`, and avoid `box-shadow` animations on large elements.

## Conclusion

Stick to transform and opacity, use `requestAnimationFrame`, and profile with Chrome DevTools to maintain buttery-smooth 60fps animations.

## 前言

最近用 [Astro](https://astro.build) 重构了个人作品集网站。这篇文章记录整个构建过程中的技术选型、架构决策和实际踩坑经验，希望能给同样在用 Astro 建站的朋友一些参考。

## 为什么选 Astro

选框架时主要考虑几个点：

- **内容驱动** — 作品集和博客都是内容型页面，需要良好的 MDX 支持
- **零 JS 开销** — 展示型页面不需要 SPA 的水合成本
- **灵活性** — 可以按需集成 React/Vue 组件，但不会被框架锁定

Astro 的 `Content Collections` 和 ` Island` 架构正好命中这些需求。MDX 文件即内容，`getCollection()` 一行代码搞定数据获取，构建时输出静态 HTML，首屏完全不需要 JavaScript。

## 项目架构

### 目录设计

```
src/
├── components/     # UI 组件（Header、Tab 面板等）
├── content/        # MDX 内容集合
│   ├── blog/       # 博客文章
│   └── works/      # 作品数据
├── data/           # 配置数据（i18n、profile）
├── layouts/        # 页面布局
├── pages/          # 路由页面
│   ├── blog/       # 博客详情页（动态路由）
│   └── works/      # 作品详情页（动态路由）
└── styles/         # 全局样式
```

`[...slug].astro` 动态路由配合内容集合，每篇 MDX 文件自动生成对应页面，新增文章只需加文件，无需改路由配置。

### Tab 式单页布局

主页面采用标签页切换的交互模式，四个面板（Works / Blog / About / Contact）通过 CSS 控制显隐：

```css
.tab-panel { display: none; }
.tab-panel.active { display: block; }
```

JS 只负责切换 `active` 类名，动画用 CSS `@keyframes` 完成。这种模式的好处是切换瞬间无等待，所有内容已在首个 HTML 请求中返回。

## CSS 暗色主题与玻璃拟态

### 主题系统

用 CSS 自定义属性实现亮/暗主题切换：

```css
:root {
  --bg: #FAFAF9;
  --text: #09090B;
  --glass-bg: rgba(255, 255, 255, 0.65);
}
[data-theme="dark"] {
  --bg: #09090B;
  --text: #FAFAFA;
  --glass-bg: rgba(12, 12, 16, 0.55);
}
```

所有组件通过 `var(...)` 引用主题变量，切换 `data-theme` 属性即可全站换肤。`prefers-color-scheme` 媒体查询处理系统偏好，JS 存一份到 `localStorage`。

### 玻璃效果踩坑

`backdrop-filter: blur()` 的玻璃效果看起来很有质感，但有两个注意点：

1. 需要两层背景：底层是页面背景，上层是半透明玻璃层，否则看不清内容
2. `backdrop-filter` 在 Firefox 上需要 `background-color: rgba(...)` 配合，纯透明背景不会生效

### 滚动条宽度导致布局偏移

这个坑比较隐蔽。内容不足一屏时没有滚动条，内容超出一屏时出现滚动条，导致页面宽度被压缩约 4px，Tab 面板里的网格布局会因此「跳」一下。

解法是 `scrollbar-gutter: stable`，让浏览器始终预留滚动条占位空间：

```css
.tab-panel { scrollbar-gutter: stable; }
html { scrollbar-gutter: stable; }
```

几行 CSS 解决了所有面板切换时的宽度抖动。

## 响应式网格布局

作品展示区使用了三列网格。这里经历了几次迭代：

1. **CSS Grid** — 整齐但所有行高度统一，短内容留白多
2. **Flexbox + wrap** — 高度独立但列对齐不稳定
3. **最终方案** — CSS Grid + `align-items: start`，既保证列对齐，又让每个卡片按内容高度伸缩

图片处理也是同样思路：去掉固定 `aspect-ratio`，用 `height: auto` 让图片按自身宽高比显示，`object-fit` 不再裁剪。

## 国际化方案

没有引入 `i18next` 之类的库——一个展示型站点不需要那么重。

方案很轻量：

- `data-i18n` 属性标记需要翻译的元素
- 一个 `i18n.ts` 对象存放所有语言的键值对
- `setLang()` 函数遍历 DOM，根据当前语言替换文本

对动态内容（作品标题、描述），使用自定义属性 `data-i18n-title`、`data-i18n-desc` 分别在 HTML 里存中英文，切换语言时读取对应属性值。

```html
<h1 data-i18n-title="title"
    data-en="Vast Desert"
    data-zh="浩渺沙漠">
  Vast Desert
</h1>
```

这种方式零依赖、零运行时开销，切换语言只是 DOM 文本替换，不需要重新渲染。

## 拖拽排序

作品卡片支持拖拽排序，使用原生 HTML5 Drag & Drop API：

- `dragstart` 记录拖拽元素
- `dragover` + `drop` 交换相邻元素位置
- 顺序存入 `localStorage`，下次访问时优先读取

实现时遇到一个细节：`dragover` 需要 `preventDefault()` 才能让 `drop` 触发，这是 HTML5 DnD 的常见陷阱。

## 构建性能

Astro 的静态构建很快，全站 8 个页面 + 几十个文件在 2-3 秒内完成。`astro build` 的输出结构清晰，每个页面独立 HTML，无需服务端运行时。

开发体验方面，`astro dev` 的 HMR 在修改 MDX 和 Astro 组件时几乎是即时的，修改 CSS 更是毫秒级刷新。

## 总结

这个项目让我更深入地理解了：

- 现代 CSS 的能力（自定义属性、backdrop-filter、scrollbar-gutter）
- Astro 内容集合的工作流（MDX → schema → 动态路由）
- 轻量级 i18n 的设计思路
- 静态站点构建的优化细节

Astro 是一个很适合内容型网站的框架，简单直接，又能按需扩展。如果是纯展示型站点，它比 Next.js 更轻、比 Hugo 等静态生成器更灵活。
